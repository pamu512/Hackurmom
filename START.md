# Start here

You have about three hours to plan a small project and build a proof of concept you can demo on this laptop. One person types. The whole team decides.

You do not need to have written code before. That is the normal case in this room. You say what it should do, what to leave out, and what you see when you click it. The agent writes the code and runs the commands. You will not use the terminal.

## Before you sit down

The machine checklist is [PREREQUISITES.md](PREREQUISITES.md). The short version:

- A coding agent is installed, you are signed in, and it can edit files and run commands in this folder. Cursor, Claude Code, and Codex all work. A browser chat that cannot touch the folder does not.
- Git is installed (`git --version` prints a version) and `git config --global user.name` and `user.email` are set.
- The person who will push has a GitHub account, and a push from this laptop already works. Create the account before the workshop, not during it.

## The only setup

1. Open this folder in your agent. Use the copy your organizer gave you (clone, zip, or USB).
2. Start a conversation that is allowed to edit files and run commands.
3. Type: **Start the hackathon**
4. Talk. Speech-to-text is better than a careful paragraph if your laptop has it.

Stay in this folder. The skills live here. Do not start in Downloads or in some other repo.

## What you will do

| When | What |
|---|---|
| First 10 minutes | Who is on the team, and what you want to build |
| Until about 0:35 | Cut the idea until a judge can see the point in one pass |
| Until about 1:00 | Decide what someone sees and does |
| Until about 1:20 | Agree that it is a web page you open in the browser |
| Until about 2:35 | The agent builds it. You click it and say what you see |
| Last 25 minutes | Rehearse the live demo and push a public GitHub repo |

Times assume the default 3-hour workshop. Your organizer's `hackathon/event.md` wins if they changed it.

## What "done" is

- The interesting part runs on this laptop, in front of a judge.
- A judge can see that in 300 seconds.
- The GitHub repo is public, has no passwords in it, and `RUN.md` says how to start the demo.
- You can name one decision you made and one thing you cut.

## What you should not do

- Do not let the agent name the project, write your pitch, or fill out a submission for you. You write those words.
- Do not paste API keys into the chat.
- Do not add login, payments, or a second service because the demo feels small. Small and running beats big and imaginary.
- Commit each working step. The build skill does this after every slice.

If you get stuck, ask a mentor. Tell them what you are trying to show a judge. You do not need to know the file names.
